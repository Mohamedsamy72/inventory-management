# 07 — REST API Specification

> **Document ID:** SPEC-07  
> **Base Route:** `/api/v1`  
> **Response Format:** JSON (camelCase)  
> **Error Standard:** RFC 7807 ProblemDetails

---

## 1. Global API Rules & Standards

1. **Deterministic Cursor Pagination:**
   List queries return `{ "items": [...], "nextCursor": "..." }`. Backend applies keyset pagination over indexed columns.
2. **Server-Side Identification:** 
   Endpoints never accept `companyId`, `actorUserId`, `createdAt`, `documentNumber`, `generatedCode`, or — on supply requests — `warehouseId` in request bodies. These properties are not declared on any command DTO, so an over-posted value is discarded by the model binder rather than relied upon to be ignored downstream.
3. **Financial Protection on DTOs (corrected — ADR-012, CR-010):**
   Financial properties (`unitCost`, `totalCost`, `averageUnitCost`, `valuation`) are returned **only** to the `Owner` role. Every other role — `Admin`, `WarehouseStaff`, `RestaurantSupervisor`, **and `User`** — receives them omitted or `null`, unconditionally and with no grant path. The earlier wording of this clause omitted `User` and is superseded.
4. **RFC 7807 Error Response:**
   ```json
   {
     "type": "https://errors.inventory.com/INSUFFICIENT_STOCK",
     "title": "Insufficient Warehouse Stock",
     "status": 400,
     "code": "INSUFFICIENT_STOCK",
     "messageEn": "The available warehouse stock is insufficient.",
     "messageAr": "الرصيد المتاح في المستودع غير كافٍ لإتمام العملية.",
     "correlationId": "c8b456e7-1234-4567-89ab-cdef01234567"
   }
   ```

## 2. Core API Endpoint Catalog

### 2.1 Authentication & Profile (`/api/v1/auth`, `/api/v1/account`)
- `POST /api/v1/auth/login`: `{ "mobileNumber": "01000000000", "password": "..." }` → Sets HttpOnly session cookie + CSRF token.
- `POST /api/v1/auth/logout`: Clears session cookie and invalidates session.
- `POST /api/v1/auth/forgot-password/otp`: Requests SMS OTP to registered mobile.
- `POST /api/v1/auth/forgot-password/verify`: Verifies OTP and grants temporary reset token.
- `POST /api/v1/auth/forgot-password/reset`: Updates password and rotates security stamp.
- `GET /api/v1/auth/csrf-token`: Returns the anti-forgery token for the session (CR-063). Required by `docs/08 §4` and `docs/10 §2`.
- `GET /api/v1/account/me`: Returns current user identity, **single** role (ADR-014), scopes, and granted permissions.
- `GET /health`, `GET /health/ready`: Unauthenticated liveness and readiness probes (CR-064). Neither discloses version or schema detail.

---

### 2.2 Items & Master Data
- `GET /api/v1/items?search=...&categoryId=...&cursor=...&limit=25`: Returns paginated item list.
- `GET /api/v1/items/{id}`: Returns item detail.
- `POST /api/v1/items`: Creates item.
  - **Request Body:** `{ "nameArabic": "لحم بقري مفروم", "categoryId": "...", "baseUnitId": "...", "purchaseUnitId": "...", "defaultSupplierId": "...", "description": "..." }`
  - **Generated by Server:** `id`, `companyId`, `generatedCode`, `createdAt`.
- `PUT /api/v1/items/{id}`: Updates master item fields.
- `DELETE /api/v1/items/{id}`: Soft deactivates item (`isActive = false`).
- `GET /api/v1/categories`, `POST /api/v1/categories`, `PUT /api/v1/categories/{id}`
- `GET /api/v1/units`, `POST /api/v1/units`, `PUT /api/v1/units/{id}`
- `GET /api/v1/suppliers`, `POST /api/v1/suppliers`, `PUT /api/v1/suppliers/{id}`
- `GET /api/v1/items/{itemId}/unit-conversions`: Retrieves active conversion factors.
- `POST /api/v1/items/{itemId}/unit-conversions`: `{ "fromUnitId": "...", "toBaseUnitId": "...", "conversionFactor": 12.0 }`

---

### 2.3 Warehouses & Restaurants
- `GET /api/v1/warehouses`, `POST /api/v1/warehouses`, `PUT /api/v1/warehouses/{id}`
- `GET /api/v1/restaurants`, `POST /api/v1/restaurants`, `PUT /api/v1/restaurants/{id}`
- `GET /api/v1/warehouses/{id}/stock`: Returns warehouse stock balances (Owner sees costs; Admin/Staff sees physical quantities only).

---

### 2.4 Receiving Orders (`/api/v1/receiving-orders`)
- `GET /api/v1/receiving-orders?warehouseId=...&status=...`: Scoped list.
- `POST /api/v1/receiving-orders`: Creates draft receiving order.
- `POST /api/v1/receiving-orders/{id}/submit`: **Posts order to warehouse stock immediately** (`INCOMING_POSTED`).
- `POST /api/v1/receiving-orders/{id}/verify`: Reconciles actual physical quantities (`INCOMING_RECONCILIATION`).
- `POST /api/v1/receiving-orders/{id}/reverse`: Safely reverses a submitted receiving order.

---

### 2.5 Supply Requests (`/api/v1/supply-requests`)
- `GET /api/v1/supply-requests`: Scoped list (Restaurant Supervisor sees their branch; Warehouse Staff sees target warehouse).
- `POST /api/v1/supply-requests`: Creates a **Draft** supply request.
  - **Request Body:** `{ "restaurantId": "...", "items": [{ "itemId": "...", "requestedQuantity": 20, "unitId": "...", "notes": "..." }] }`
  - **Derived / generated by the server:** `id`, `companyId`, **`warehouseId`**, `documentNumber` (`REQ-…`), `baseQuantity` per line.
  - ⚠️ **`warehouseId` is NOT part of the request body (ADR-028).** The DTO does not declare the property, so an over-posted value is discarded by the model binder. The warehouse is derived from `restaurants.default_serving_warehouse_id`. If the restaurant has no active serving warehouse → `409 SERVING_WAREHOUSE_UNAVAILABLE`; there is **no fallback to another warehouse**.
- `POST /api/v1/supply-requests/{id}/items` — add a line. **Draft only.**
- `PUT /api/v1/supply-requests/{id}/items/{lineId}` — edit a line. **Draft only.**
- `DELETE /api/v1/supply-requests/{id}/items/{lineId}` — remove a line. **Draft only.**
- `POST /api/v1/supply-requests/{id}/submit` — `Draft → Submitted`. Requires at least one line. **Zero stock effect.**
- `POST /api/v1/supply-requests/{id}/cancel` — per `docs/04 §8.1`.
- `POST /api/v1/supply-requests/{id}/fulfill`: Warehouse fulfils and creates a `Supply` in state **`Prepared`** (`SUP-…`) — **not** `Dispatched` (ADR-017, CR-020). **Zero stock effect.**

---

### 2.6 Supplies & Confirmation (`/api/v1/supplies`)
- `GET /api/v1/supplies?status=...`: Returns scoped supplies list.
- `POST /api/v1/supplies/{id}/dispatch`: Transitions `Prepared → Dispatched` (NO STOCK EFFECT). Raises a non-blocking sufficiency advisory when a line exceeds `available` (ADR-019).
- `POST /api/v1/supplies/{id}/cancel`: `Prepared` only.
- `POST /api/v1/supplies/{id}/confirm`: **Restaurant confirms receipt (REDUCES WAREHOUSE STOCK).**
  - **Headers:** `X-Idempotency-Key: <UUID>`
  - **Request Body:** `{ "items": [{ "itemId": "...", "receivedQuantity": 18, "notes": "2 KG damaged in transit" }] }`
  - **Effect:** Deducts 18 from warehouse stock, records discrepancy for 2.

---

### 2.7 Stock Counts & Discrepancies
- `GET /api/v1/stock-counts`, `POST /api/v1/stock-counts` (Start count).
- `POST /api/v1/stock-counts/{id}/record`: Records physical count quantities.
- `POST /api/v1/stock-counts/{id}/approve`: Admin/Owner approves count → posts `PHYSICAL_ADJUSTMENT`.
- `GET /api/v1/discrepancies`, `POST /api/v1/discrepancies/{id}/resolve`

---

### 2.8 Consumption (`/api/v1/consumption`)
- `POST /api/v1/consumption`: Logs kitchen ingredient usage (Statistical only; zero stock impact).

---

### 2.9 User Management & Scope (`/api/v1/users`)
- `GET /api/v1/users`, `POST /api/v1/users`, `PUT /api/v1/users/{id}`
- `PUT /api/v1/users/{id}/scope`: Assigns authorized warehouses and restaurants.
- `PUT /api/v1/users/{id}/permissions`: Sets explicit user grants/denials.

---

### 2.10 Audit Logs (`/api/v1/audit`)
- `GET /api/v1/audit?search=...&actorId=...&entityType=...`: **Owner Role ONLY** (every other role receives HTTP 403, including a user explicitly granted `audit:view` — the code is non-grantable, ADR-012).
- `GET /api/v1/audit/activity`: Arabic activity stream. **Owner Role ONLY, no grant path** (ADR-013).

**Idempotency (`docs/30 §6.1`).** `X-Idempotency-Key` is **REQUIRED** on `/supplies/{id}/confirm`, `/receiving-orders/{id}/submit`, `/verify`, `/reverse`, and `/stock-counts/{id}/approve`; **RECOMMENDED** on `/supply-requests` and `/supply-requests/{id}/fulfill`; optional elsewhere. Missing on a required endpoint → `400 IDEMPOTENCY_KEY_REQUIRED`. Same key with a different payload → `409 IDEMPOTENCY_KEY_REUSE`.
