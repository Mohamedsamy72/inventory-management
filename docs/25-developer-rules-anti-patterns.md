# 25 — Developer Rules & Forbidden Anti-Patterns

> **Document ID:** SPEC-25  
> **Topic:** Strict Architectural Rules, Forbidden Coding Practices, and Engineering Invariants

---

## 1. Top Architectural Anti-Patterns (STRICTLY FORBIDDEN)

| Anti-Pattern | Description & Why It Is Banned | Correct Engineering Alternative |
| :--- | :--- | :--- |
| **Direct Stock Writes** | Writing directly to `StockBalance` or sending balance updates from the frontend. | All balance changes must be generated by formal stock postings in `StockLedger`. |
| **Generic Repository Bloat** | Creating `IGenericRepository<T>` abstractions that merely wrap EF Core DbSet without added value. | Use EF Core DbContext directly in Application handlers or create domain-specific aggregates. |
| **Client-Side Calculation Trust** | Accepting client-calculated variances, base quantities, or costs in API request DTOs. | The server independently fetches configured conversion rates and calculates math. |
| **Frontend Security Hiding** | Relying on UI `v-if` / React conditional rendering to hide financial fields or audit logs. | Server-side DTO projection masks columns; controllers enforce role denial (HTTP 403). |
| **Fake Dashboard Zeros** | Hardcoding `0` or mock arrays when backend APIs are failing or unavailable. | Show explicit loading skeletons or honest Arabic error banners with retry triggers. |
| **Destructive Database Drops** | Using `EnsureDeleted()` or running `DROP DATABASE` in startup scripts (`run-local.bat`). | Use deterministic EF Core migrations (`dotnet ef database update`). |
| **Untrusted Client Identity** | Reading `CompanyId` or `UserId` from JSON body payloads or route params. | Extract identity strictly from authenticated server-side `ClaimsPrincipal`. |
| **Client-Selected Serving Warehouse** | Declaring a `WarehouseId` property on the supply-request command DTO — even a hidden one, even one that is "validated". A validated client value still leaves a value some future handler may trust. | Do not declare the property at all. Derive the warehouse from `restaurants.default_serving_warehouse_id` (ADR-028). Removing the input removes the class of bug, not one instance of it. |
| **Silent Warehouse Fallback** | Choosing "any available warehouse" when a restaurant's serving warehouse is inactive. | Fail with `409 SERVING_WAREHOUSE_UNAVAILABLE`. A silently redirected requisition is worse than a refused one. |
| **Placeholder Surfaces for Deferred Features** | Shipping a `/reports` route, a sample chart, a mock KPI card, or a "coming soon" screen because the real feature is scheduled later. | Render nothing. A placeholder chart is fake data with better styling (ADR-029, `docs/17 §4.6`). |
| **Trimming Ledger Metadata** | Dropping `unit_cost`, `actor_user_id`, or `occurred_at` from a ledger row because "reports are deferred and nothing reads it". | Record it. A cost or actor not captured at posting time is unrecoverable forever (`docs/17 §4.1`). |
| **Substituting the Database Engine** | Using SQL Server, MySQL, or Oracle because one is already installed and PostgreSQL is not. | Install PostgreSQL 16+. The specification depends on `xmin`, `ON CONFLICT … RETURNING`, `jsonb`, range partitioning, `pg_trgm`, and `ar-x-icu` — none of which transfers (ADR-027). |
| **SQL Server Concurrency Idioms** | Adding a `byte[]` / `BYTEA` rowversion column for optimistic concurrency. | PostgreSQL has no auto-maintained rowversion. Map the `xmin` system column (ADR-022). |

## 2. Inviolable Backend Code Guidelines

1. **Floating Point Ban:** Never use `float` or `double` for currency, stock quantities, conversion multipliers, or costs. Always use `decimal`.
2. **UTC Timestamps:** All database timestamps and API dates are stored and transmitted in UTC (`DateTimeOffset.UtcNow`). Timezone formatting is handled by the frontend.
3. **No Unbounded Queries:** Every list query in EF Core must specify `.Take(limit)` or Keyset pagination parameters.
